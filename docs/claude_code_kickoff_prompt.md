# Claude Code 依頼プロンプト — AKB48 Mail レスキューツール(S-1 開始)

以下をそのまま Claude Code の最初のメッセージとして貼り付けて使う。
前提: リポジトリ直下に `CLAUDE.md`(CLAUDE_akbmail_rescue.md をリネーム)、`docs/requirements.md`(要件定義書)、`reference/` に rescue.py / stitch.py / synth_gen.py / sample_31s.mp4 を配置済みであること。

---

AKB48 Mail アプリ版のサービス終了に伴い、ファンが自分の画面収録動画からメール本文をバックアップできるブラウザ内完結の Web ツールを作ります。あなたへの依頼は実装フェーズです。設計と中核アルゴリズムは検証済みで、`reference/` の Python 実装が「アルゴリズムの正」です。

## 最初にやること

1. `CLAUDE.md` と `docs/requirements.md` を読む。特に不変条件 INV-1〜7 と要件 §2(法的前提)は、以降のすべての実装判断より優先する
2. `reference/rescue.py` と `reference/stitch.py` を読み、閾値・棄却条件・処理フローを把握する
3. Vite + React + TypeScript でプロジェクトを初期化し、CLAUDE.md 記載の開発コマンドが動く状態にする

## 今回のスコープ: スライス S-1 のみ

動画→フレーム抽出(WebCodecs、6fps)+フレーム分類(list / loading / detail / fullscreen_image)までを実装してください。S-2 以降(セグメンテーション、スティッチ、OCR、UI)には着手しないでください。

完了の定義:
- `reference/sample_31s.mp4`(タップ方式)で loading イベント 8 回・7 メール区間、`reference/sample_scroll_24s.mp4`(連続スクロール方式)で境界イベント 9 回・10 メール区間が検出されるログが出ること(いずれも reference/rescue.py 系の実測値と同一)
- 境界検出は「本文ブランク+ヘッダー有無」の複合判定であること(requirements §6 F-3。両方式を単一の検出器で処理する)
- 分類ロジックが rescue.py と同じ相対座標・同じ閾値であること(INV-4, INV-5)
- 保持フレームが常に 30 枚以下であること(INV-2)。フレームを配列に貯めてから処理する実装は不可
- 開発用の簡易 UI(ファイル投入+分類結果のタイムラインログ表示)があること。本番 UI は S-4 なので作り込まない
- Vitest で分類関数の単体テストが通ること(閾値境界のテストケースを含む)

## 守ってほしい進め方

- INV に抵触しそうな実装判断(例: デコードの都合でフレームを溜めたい、CDN からアセットを引きたい)が出たら、実装せずに選択肢と推奨を提示して私に確認する
- Python 版と数値挙動を変えたくなった場合も同様。勝手に「改善」しない
- HEVC が WebCodecs でデコードできない環境への ffmpeg.wasm フォールバックは、今回はスタブ(未対応メッセージ表示)でよい。本実装は S-5
- 進捗はスライス完了時に、サンプル動画での検証ログを添えて報告する

## 禁止事項(重要)

- 動画・フレーム・解析結果を外部送信するコードをいかなる形でも書かない(INV-1)。テレメトリ・エラートラッキング SaaS も導入しない
- クラウド保存・SNS 共有など要件 §8 スコープ外機能の追加提案はしない(法的前提 §2 に抵触するため)

まず 1〜3 を実施し、プロジェクト構成案とフレーム抽出の実装方針(WebCodecs の使い方、ウィンドウ処理の設計)を短く共有してから実装に入ってください。
