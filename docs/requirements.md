# AKB48 Mail レスキューツール 要件定義書 v1.0

作成日: 2026-08-26 / 作成: Masa + Claude (claude.ai)
参照実装: `rescue.py`(メール分割) / `stitch.py`(縦スティッチ) / `synth_gen.py`(検証データ生成)

---

## 1. 背景と目的

AKB48 Mail アプリ版のサービス終了発表を受け、アプリ内にのみ保存されているメール本文をファン自身の手でバックアップできる手段を無償提供する。画像はアプリ内の公式ダウンロード機能で保存できるため、本ツールの主目的は**メール本文(テキスト+レイアウト)の保全**である。

ファンは iOS / Android 標準の画面収録機能でメールをスクロール閲覧した動画を撮り、本ツール(Webアプリ)に読み込ませる。ツールは動画を解析し、メール1通ごとの縦長PNG画像とメタデータを生成する。

## 2. 法的前提(実装判断に直結するため必読)

- 本ツールは**利用者本人が、本人の端末上・ブラウザ内で実行する私的複製の道具**である。運営者(配布者)が利用者のコンテンツに触れる構成は自炊代行判例に照らしてNG。
- したがって「動画・生成物を一切外部送信しない」ことは機能要件ではなく**成立条件**。CLAUDE.md の INV-1 として厳守。
- 生成物の共有・再配布は利用者の責任であり、ツール側はSNS共有機能等を持たない。

## 3. 対象ユーザーと利用環境

- AKB48 Mail アプリ版の購読者(iOS / Android)。技術リテラシーは想定しない。
- 実行環境: PC またはスマホのモダンブラウザ(Chrome / Safari / Edge 最新2バージョン)。
- 想定入力: 縦持ち画面収録動画(H.264/HEVC MP4)、1本あたり数分〜数十分、複数本の連続投入あり。
- 検証済み実機プロファイル: iPhone 15 Pro Max(1290×2796, 60fps, HEVC)。他解像度は相対座標で吸収する。

## 4. ユーザーフロー

1. トップページで録画手順ガイドを読む(§5)
2. 動画ファイルをドラッグ&ドロップ(複数可)
3. ブラウザ内で解析(進捗バー+残り時間表示)
4. 結果プレビュー: メール一覧(サムネイル+日時)で確認、不要品を除外
5. ZIP 一括ダウンロード(PNG群+ `metadata.json`)

## 5. 録画手順ガイド(アルゴリズム精度の前提条件)

ツール内に明示するユーザー向けルール。これを守った動画を「準拠入力」とし、精度目標(§9)は準拠入力に対して定義する。

実機確認済みの前提: アプリ版のデータは Apple ID / ストアアカウントに紐付き(iOS→Android移行不可)、メール詳細で末端まで引っ張ると**次のメールのページに切り替わる**(連続スクロール閲覧が可能)。一覧への復帰は左上の戻るボタンのみ、左右スワイプ遷移はなし。

### 5.1 推奨方式: 連続スクロール録画
実測値: 2.4秒/通(24秒・10通の実録画より)。1,000通≈40分、3,000通≈2時間。タップ操作ゼロ。
1. 最初のメール(最新または最古)を開いて録画開始
2. ゆっくりドラッグでスクロールし、メール末尾で引っ張って次のメールへ
3. **ページが切り替わったら2秒静止**(本文の遅延読み込み待ち。読み込み中の白画面が境界検出のシグナルになるため、この静止は精度上も必須)
4. 以降繰り返し。手が疲れたら録画を止めて分割してよい

### 5.2 共通ルール
- 長いメールは**ゆっくりスクロール**(フリックせずドラッグ)し、末端で2秒静止
- 画像の全画面表示は開いてもよいが、保存はアプリの↓ボタン推奨
- 1動画は5分以内を推奨(長い場合は分割して録画)
- 画面の明るさ最大、ダークモードOFF、通知バナーOFF、着信は機内モード推奨

### 5.3 代替方式: 一覧からのタップ録画
連続スクロールが使いにくい場合の代替。実測値: 約4.4秒/通。メールを開いたら2秒静止→戻る、を繰り返す。境界検出は同一の検出器で処理される(F-3)。

### 5.4 iOS 放置運用レシピ(AssistiveTouch カスタムジェスチャ)
連続スクロール方式により、レシピは**「ゆっくり上方向ドラッグ→2〜3秒待機」1動作の連続再生のみ**に簡素化された(タップ・行位置合わせ・ズレ補正は不要)。ガイドページに設定手順書(スクリーンショット付き)を含める。長文メールでは1回のドラッグで末端に達しない場合があるが、その場合も同じドラッグの繰り返しで自然に進むため問題ない。

### 5.5 Android の場合
- Android ユーザーはストアアカウントで PC エミュレータに復元できる可能性があり、その場合 adb による完全自動取得(タップ・スクロール・スクリーンショットのスクリプト実行)が本人実行の範囲で可能
- 本ツールのスコープ外だが、ガイドから別文書(adb 手順書)へリンクする。エミュレータでの動作可否・FLAG_SECURE の有無は配布前に要検証

## 6. 機能要件

### F-1 動画取り込み
- MP4(H.264/HEVC)をブラウザ内でデコードしフレーム抽出(基準 6fps)
- WebCodecs API を第一候補、非対応ブラウザは ffmpeg.wasm フォールバック(2026-08-26: Windows Chrome は GPU に HEVC 復号が無いと WebCodecs で HEVC 不可と実確認したため、フォールバックを S-5 から S-1 に前倒し。処理時間は実時間の約 6〜7 倍。コアはセルフホスト、入力は WORKERFS マウントで丸ごとコピーしない。注: `@ffmpeg/core` は GPL-2.0 ビルドであり、MIT での配布方針との整合を要確認)
- **チャンク処理必須**: 動画全体をメモリ展開しない(INV-2)

### F-2 フレーム分類
参照実装 `rescue.py` の方式を移植する。
- 本文領域(相対座標 y: 0.28–0.90)の非白ピクセル率で list / loading / detail を判定
- 上下端(y: 0.10–0.16, 0.92–0.98)の暗色率 >0.5 で fullscreen_image と判定
- 閾値: loading <0.02 / list <0.15 / detail ≥0.15(参照実装と同値。変更時は回帰テスト必須)

### F-3 メール単位のセグメンテーション
- 境界シグナル: 本文領域ブランク(非白率 <0.02)の立ち上がり。連続スクロール方式ではページスワップ直後に「ヘッダー表示+本文ブランク(読み込み中)」状態が0.5〜1秒現れることを実録画で確認済みであり、**ブランク+ヘッダー有無の複合判定**を境界とする(タップ方式のローディング画面も同条件で検出されるため、両方式を単一の検出器で処理する)
- ヘッダー有無判定: アバター領域(相対座標 x: 0.06–0.15, y: 0.145–0.19)の彩度画素率 >0.15。彩度画素の定義は **HSV の S > 0.2**、実装は整数判定 `(max(R,G,B) − min(R,G,B)) × 5 > max(R,G,B)`(max=0 は非該当)とする(2026-08-26 実測で確定: ヘッダー付きブランクは 0.30–0.38、遷移直前フレームは 0)
- 境界に該当しない loading フレーム(ヘッダー無しの遷移途中)は境界にも区間にも含めない
- 区間内の detail フレームから、隣接 pHash 距離 ≤2 の安定フレーム群を抽出し、情報量最大のものを代表フレームとする(タップ方式)。連続スクロール方式では区間内フレームを F-4 でスティッチする
- pHash 距離 ≤6 の既出メールは重複として排除

### F-4 縦スティッチ(長文メール対応)
参照実装 `stitch.py` の方式を移植する。
- 固定領域(ステータスバー+戻るボタン行)を除去後、連続フレーム間の縦変位を位相相関で推定
- 相関応答 <0.7 または |dx|>12px は画面遷移とみなし棄却、dy<2px は静止として棄却(2026-08-26: 応答閾値を 0.05→0.7 に変更。実録画のページ切替アニメーションが応答 ≈0.59・dy≈900px で誤採用されたため。合成動画の採用対は最小 0.815 で影響なし)
- 新規出現領域のみをキャンバス下端に継ぎ足す(直前フレーム全体での上書きは行わない。collapsing header の二重描画対策、2026-08-26)
- 合成検証結果: 4736px の正解データに対し高さ誤差 0px、8/8 バンドで一致率 ≥0.997
- 実装メモ(2026-08-26): 相関は 1/2 縮小(INTER_AREA)で行い dx/dy を原寸換算、応答 [0.55, 0.85) の対だけ原寸で再判定(合成 8/8・実録画 38 対中 37 対で原寸と同じ採否)。自前 FFT で cv2.phaseCorrelate を移植(getOptimalDFTSize へのゼロ詰め、窓 = √(Hanning 2D)、非スケール逆変換、5×5 重み付き重心)。合成回帰で cv2 と 35 対一致。固定領域は「ステータスバー h×0.055」+「採用対の行差分から自動推定した不変行」(実機 195px)
- 注意: OpenCV.js 標準ビルドに `phaseCorrelate` が含まれない場合がある。含まれない場合は FFT(自前実装可)による位相相関、それも困難なら matchTemplate による帯探索をフォールバックとする。**いずれの実装でも合成回帰テスト(§10)の通過を移植完了の定義とする**

### F-5 メタデータ抽出
- 代表フレームのヘッダー右上(相対座標 x: 0.55–1.0, y: 0.13–0.18)を Tesseract.js(jpn+eng)で OCR し、`YYYY-MM-DD HH:MM` を抽出
- 送信者名(ヘッダー左 x: 0.17–0.55, y: 0.14–0.17, OCR)も併せて抽出。失敗時は `unknown_NN` 連番(NN は何通目か、rescue.py と同じ)
- 実装メモ(2026-08-26): tesseract.js を Worker 内で使用、アセットは同一オリジンから配信。jpn は標準 tessdata(fast 版は「渋」を誤読)。日時は eng 数字のみ(whitelist)、差出人は jpn+eng。区間内の detail フレームを順に試し取得できたら停止(上限 8 回)。実録画: 31 秒版 6/7 取得(残り 1 はヘッダーが画面外)、24 秒版 8/10
- 本文テキストの OCR 化は **MVP スコープ外**(オプションとして将来検討)

### F-6 出力
- メールごとに `mail_<timestamp>.png`(ステータスバー除去済み・縦スティッチ済み)
- `metadata.json`: `[{file, timestamp, sender, source_video, frame_range}]`
- fullscreen_image の安定フレームも `image_NNN.png` として同梱(参考品質)
- ZIP 一括ダウンロード(JSZip 等、ブラウザ内生成)

### F-7 プレビューと除外
- 解析後にサムネイル一覧を表示し、チェックボックスで除外可能
- タイムスタンプ未取得(`unknown`)のメールは手入力で日時修正可能

## 7. 非機能要件

- **NF-1 完全ローカル処理**: 動画・フレーム・生成物を外部送信するコードを一切含まない。アナリティクスも計測 SaaS を使わず、導入するなら自ホストかつ集計イベントのみ
- **NF-2 性能**: 5分動画(1800フレーム@6fps)を一般的なPCで10分以内、スマホで20分以内に処理
- **NF-3 メモリ**: ピーク使用量 1.5GB 以下(スマホブラウザのタブキル回避)
- **NF-4 中断耐性**: 動画単位で処理を分割し、タブクラッシュ時も処理済み分は IndexedDB から復元可能(2026-08-26 実装: 出力 PNG・OCR 結果・区間情報を届くたびに保存。起動時に処理中だったジョブは「中断」として一覧に出し、処理済み分の閲覧・ZIP が可能。同じ動画を再投入すると再解析)
- **NF-5 オフライン動作**: 初回ロード後はネットワーク遮断状態でも全機能が動作すること(NF-1 の検証手段を兼ねる)

## 8. スコープ外(MVP)

- 本文のテキスト化(OCR)、メンバー別の自動フォルダ分け
- ブラウザ版 AKB48 Mail への対応(メール配信型のため対象外)
- 他のアイドルメールサービスへの汎用化(将来の横展開候補)
- iOS/Android ネイティブアプリ化

## 9. 精度目標(準拠入力に対して)

- メール取りこぼし率: ≤2%(50通中1通まで)
- 重複出力率: ≤5%
- スティッチ破綻(継ぎ目ズレ視認)率: ≤5%
- タイムスタンプ OCR 成功率: ≥90%

## 10. テスト方針

- `synth_gen.py` 相当の合成動画生成を JS 側テストに組み込み、スティッチ回帰テストを CI 化(高さ誤差 ≤1%、バンド一致 ≥7/8 を合格ライン)
- 実録画サンプルでの回帰基準を2本固定する: タップ方式31秒版(7通+画像2枚)、連続スクロール方式24秒版(境界イベント9回・10通)
- 全通が難しいユーザー向けの優先順(ガイドに記載): スター済み → 記念日・イベント期 → 直近から遡る
- 未検証リスク(実録画での確認が必要): iOS ラバーバンドの負方向変位、画像領域での相関低下、機種別の固定ヘッダー高さ

## 11. リリース計画との接続

- 配布: 静的ホスティング(GitHub Pages)、OSS。ライセンスは **GPL-3.0-or-later**(2026-08-26 決定: 同梱する ffmpeg.wasm コアが GPL のため。有料化・組込みの予定なし)
- 導線: メモリーアプリのウェイトリストへのリンクは **当面設置しない**(2026-08-26 オーナー判断。核はメール本文の救出であり、必要になった時点で追加)
- サービス終了日までの期限があるため、精度より先に「動く MVP の公開」を優先する
